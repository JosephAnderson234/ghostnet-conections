B / CAPTURA

Lecturas de TTY sin eco

Un hook de n_tty_read observa lecturas de procesos seleccionados cuando L_ECHO está desactivado. El README describe un anillo de ocho entradas.

/proc/rootpass presenta contadores, capturas recientes y, según las credenciales del lector, la línea root: de /etc/shadow.

05 / Detalles técnicos

Por qué importa el punto de retorno

Un kretprobe permite registrar información al entrar a una función y actuar cuando termina.

En netlink: longitud del skb

El handler de entrada guarda el skb y su longitud previa. Si el socket coincide y el relleno termina sin error, el handler de retorno restaura esa longitud con skb_trim.

En procfs: contador de seq_file

Se guarda seq->count antes de tcp4_seq_show o tcp6_seq_show. Restaurarlo hace que la línea agregada no quede en la lectura.

En TTY: condiciones de captura

El README limita la captura a procesos como sshd, login, su y sudo con eco desactivado. Copia como máximo 128 bytes por lectura.

En descarga: orden de limpieza

Primero se elimina la entrada procfs; luego se desregistran, en orden inverso, únicamente los hooks cuyo registro sí tuvo éxito.

06 / Alcance e interpretación

Qué demuestra y qué no

La ausencia de una fila en una herramienta no prueba que el socket no exista. La observación depende de la ruta de datos usada por cada herramienta.

El tráfico continúaEl módulo modifica ciertas salidas formateadas; no interrumpe accept() ni los paquetes.
conntrack queda fueraconntrack -L y /proc/net/nf_conntrack no usan las rutas filtradas aquí.
El listener depende del parámetroCon hide_listen=0, un socket en LISTEN puede seguir apareciendo.
La captura tiene límitesSolo observa TTY, el anillo conserva ocho posiciones y una lectura sin fallo no garantiza que la copia de memoria tenga éxito.
Depende del kernelSímbolos, firmas y posiciones de argumentos pueden cambiar. El README cita pruebas en Ubuntu con kernel 7.0.0-30-generic.
Requiere privilegiosLa línea de /etc/shadow depende de las credenciales del lector de /proc/rootpass.
